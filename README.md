# Vector-Search-Similarity-Detection | Oracle AI Vector Search

## 1. Project Overview
The goal of this project is to implement a system for detecting document duplicates and similarity using **Oracle AI Vector Search**. Unlike standard text searches that look for exact word matches, this solution uses vector embeddings to find documents that are "close" in meaning, even if they use different vocabulary. Therefore, documents with similar meaning will have vectors that are close to each other.

## Solution Architecture
 
```
.docx files on Windows
      │
      ▼  docker cp
Oracle 26ai (Docker container)
      │
      ├─ 1. Store file as BLOB
      ├─ 2. Extract text → CLOB  (via CTX_DOC.IFILTER)
      ├─ 3. Generate vector → VECTOR(384)  (via ONNX model)
      └─ 4. Query cosine distance between documents
```
 
---
 
## Data Model
 
```sql
CREATE TABLE documents (
    id               NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    file_name        VARCHAR2(255),
    file_binary      BLOB,       -- the raw .docx file
    text_content     CLOB,       -- extracted plain text
    embedding_vector VECTOR(384) -- semantic vector
);
```
 
---
 
## Steps
 
### 1. Load the embedding model into Oracle
 
The `all-MiniLM-L6-v2` model (converted to ONNX) is copied into the container and loaded using `DBMS_VECTOR.LOAD_ONNX_MODEL`. This lets Oracle generate vectors natively inside the database.
 
### 2. Load documents
 
Each `.docx` file is copied into the Docker container with `docker cp`, then inserted into the database as a binary BLOB.
 
### 3. Extract text
 
Oracle Text's `CTX_DOC.IFILTER` reads the BLOB and extracts the plain text content into the CLOB column.
 
### 4. Generate vectors
 
```sql
UPDATE documents
SET embedding_vector = VECTOR_EMBEDDING(doc_model USING text_content AS DATA);
```
 
### 5. Query similarity
 
**Compare all documents against each other:**
 
```sql
SELECT a.file_name, b.file_name,
       VECTOR_DISTANCE(a.embedding_vector, b.embedding_vector, COSINE) AS score
FROM documents a
JOIN documents b ON a.id < b.id
ORDER BY score;
```
 
**Find documents most similar to a given file:**
 
```sql
SELECT b.file_name,
       VECTOR_DISTANCE(a.embedding_vector, b.embedding_vector, COSINE) AS score
FROM documents a
JOIN documents b ON a.id <> b.id
WHERE a.file_name = 'document.docx'
ORDER BY score
FETCH FIRST 5 ROWS ONLY;
```
 
---
 
## Score Interpretation
 
| Score | Meaning |
|---|---|
| `0.00` | Identical |
| `< 0.03` | Near-duplicate |
| `< 0.10` | Very similar |
| `< 0.18` | Similar |
| `< 0.40` | Different |
| `≥ 0.40` | Very different |

## Test Documents
 
The system was tested with several documents: an original file, an exact copy, a slightly modified version, a partial copy, and a completely unrelated document (different topic). Results confirmed that the vector distances correctly reflected the actual relationship between files.

## How to Run
 
> Requires Oracle 23ai Free running in Docker.
 
1. Run Oracle 23ai Free in Docker and create a directory object pointing to `/opt/oracle/doc_files`.
2. Copy the ONNX model and `.docx` files into the container using `docker cp`.
3. Load the model with `DBMS_VECTOR.LOAD_ONNX_MODEL`.
4. Run the SQL steps in order: create table → load files → extract text → generate vectors → query.
Screenshots of the query results are included in the `/screenshots` folder.
